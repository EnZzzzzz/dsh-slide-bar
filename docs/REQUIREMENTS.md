# 需求文档：dsh 左侧边栏面板（activity bar + 文件浏览器）

## 背景

dsh（DeepSeek Harness）的 Web UI 左侧边栏目前只有一个固定的「会话/工作区浏览器」区域，没有让插件贡献可切换功能面板的机制。希望把左侧边栏做成 VSCode 那样的形态：左边缘一列竖排图标（activity bar），点击图标切换整个面板区的内容，不同功能面板由不同插件提供。

## 目标

1. 左侧边栏支持「图标列 + 可切换面板」的扩展机制，后续可以陆续接入新的功能面板。
2. 落地第一个面板：文件浏览器（资源管理器），参照 VSCode 资源管理器的体验。

## 功能需求

### R1 侧边栏面板切换机制（activity bar）

- R1.1 侧边栏展开状态下，左边缘显示一条竖排图标列，每个图标对应一个面板。
- R1.2 点击图标切换面板区内容；当前激活面板的图标有高亮态。
- R1.3 既有的「会话/工作区浏览器」是默认面板，是图标列上的第一个图标；其现有功能与外观不因此改变。
- R1.4 侧边栏折叠成窄条（rail）时，面板图标仍出现在窄条中；点击面板图标会选中该面板并展开侧边栏。
- R1.5 面板选择状态跨页面刷新保留（持久化）。
- R1.6 如果持久化的选择指向一个已不存在（插件被移除）的面板，界面回退到默认的会话面板，不出现空白或报错。
- R1.7 新面板可以通过新增插件的方式接入，不需要改动已有面板的代码。
- R1.8 侧边栏既有的折叠/展开动画行为保持不变。

### R2 文件浏览器面板（资源管理器）

- R2.1 面板以文件树形式展示目录内容，树根为当前会话的工作目录；没有当前会话时回退到最近使用的工作区目录；两者都没有时显示空态提示（中文）。
- R2.2 文件树按需懒加载：初始只加载根目录一层，展开目录时才加载其子层。
- R2.3 排序：目录在前、文件在后，各自按名称排序。
- R2.4 目录可展开/折叠（chevron 指示）；展开状态跨面板切换和页面刷新保留。
- R2.5 点击文件用操作系统默认程序打开该文件。
- R2.6 面板头部提供：刷新（重新拉取已展开目录的内容）、显示/隐藏隐藏文件（dot 文件）的开关。
- R2.7 加载中、加载失败（附重试入口）、目录内容过多被截断时，均有明确的界面反馈。
- R2.8 文件浏览能力在本地桌面部署和无头/远程（SSH）部署下都可用，不依赖某种特定的目录选择器组合。

## 约束

- 面板必须是 dsh 的正规插件（cordis 插件），通过 dsh 的 UI 扩展机制接入，不 hack 页面。
- 浏览器端不能直接访问文件系统，文件数据必须经过 dsh host 的既有通信通道获取。
- 界面文案为中文；样式遵循 dsh 现有主题体系。
- 不破坏 dsh 现有功能与测试基线（含快照测试）。

## 验收标准

1. 侧边栏出现图标列，至少含「会话」和「资源管理器」两个图标；点击可互相切换，激活图标高亮。
2. 折叠侧边栏后图标仍在，点击「资源管理器」图标会展开侧边栏并显示文件树。
3. 刷新页面后，面板选择和文件树展开状态保持。
4. 文件树根目录为当前会话工作目录；展开目录可逐层浏览；目录在前、文件在后按名称排序。
5. 点击文件能调起系统默认程序打开。
6. 本地桌面（有显示器）和远程/无头两种部署形态下文件树都能正常加载。
7. dsh 仓库的单元测试、GUI 测试、浏览器快照回放测试全部通过。

## 明确不做

- 编辑器内打开/预览文件（无编辑器面板）。
- 文件的新建/删除/重命名/拖拽移动。
- 文件系统变更的自动监听刷新（手动刷新即可）。
- 面板图标的拖拽排序。
- 会话 cwd 目录已被删除时回退到工作区路径（当前显示错误+重试即可，后续可优化）。
